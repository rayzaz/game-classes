# Установка v42.8.1 — старые пароли + доступы уже опубликованным персонажам

Обновление состоит из двух частей: GitHub-проект сайта и Google Apps Script. Нужно обновить обе.

## 1. GitHub-проект

Распакуй архив поверх `C:\game-classes`:

```powershell
Expand-Archive `
  "$HOME\Downloads\game-classes-access-v42.8.1.zip" `
  -DestinationPath "C:\game-classes" `
  -Force

cd C:\game-classes
```

Проверка:

```powershell
npm ci
npx tsc --noEmit
npm run build
```

Публикация через GitHub:

```powershell
git status
git add .
git commit -m "Migrate legacy passwords and backfill portal access"
git push origin main
```

Если Netlify связан с GitHub, он сам задеплоит новый commit. `netlify deploy --prod` не нужен.

## 2. Google Apps Script

Открой Apps Script, который используется в `CHARACTER_SERVICE_URL`.

Полный файл для замены:

`CharacterService_DONORLESS_ACCESS_v42.8.1.gs`

В редакторе Apps Script:

1. открой основной файл Character Service;
2. `Ctrl+A`;
3. удали старый код;
4. вставь весь `CharacterService_DONORLESS_ACCESS_v42.8.1.gs`;
5. сохрани;
6. **Deploy → Manage deployments → Edit → New version → Deploy**.

При обновлении существующего deployment URL `CHARACTER_SERVICE_URL` остаётся тем же.

## 3. Перенос старых паролей и выдача доступа четырём уже опубликованным

После того как GitHub/Netlify и Apps Script обновлены:

1. зайди в админку;
2. открой раздел `Анкеты персонажей`;
3. нажми `🔐 Синхронизировать доступы`;
4. подтверди действие.

Система автоматически:

- создаст или откроет `[🔐] Черный клевер — ДОСТУПЫ`;
- создаст вкладку `Старые пароли` и перенесёт туда полный старый список;
- перенесёт старые рабочие аккаунты из `PORTAL_USERS_JSON*` во вкладку `Пользователи`, сохранив их прежние пароли;
- найдёт уже опубликованные анкеты без аккаунта;
- создаст для них логины и новые 8-значные пароли;
- покажет новые логины/пароли прямо под кнопками в разделе анкет.

Эту синхронизацию безопасно запускать повторно: уже существующие аккаунты не получают новый пароль.

## 4. Что будет с новыми анкетами дальше

После успешной публикации новой анкеты система сама:

- использует `characterId` как логин;
- генерирует случайный 8-значный пароль;
- записывает доступ в закрытый Google-реестр;
- показывает его в блоке `🔑 Доступ игрока в кабинет`;
- позволяет позже посмотреть или сбросить пароль.

## 5. Проверка

После синхронизации:

- открой ссылку на закрытый Google-реестр;
- проверь вкладку `Старые пароли`;
- проверь вкладку `Пользователи`;
- у четырёх уже опубликованных без доступа должны появиться новые строки с логином и паролем;
- в админке новые четыре пары логин/пароль будут показаны сразу после синхронизации;
- старые игроки должны входить прежними логинами и паролями;
- новые игроки — новыми выданными данными.
